# BA Medicale Live Quiz

Canonical public event slugs come from `quiz/config.json`; verbatim questions and four choices live in `quiz/questions.json`. No correct-answer metadata belongs in Git, public assets, or browser code. Do not publish the highlighted source PDF.

`scripts/quiz/backend.js` is included in the existing attendance Apps Script bundle. Dedicated quiz dispatch preserves attendance/download behavior. Deploy to the existing owner-executed web app; retain its endpoint, scopes, and Restricted tracker. Before `setupQuiz`, the owner sets `QUIZ_KEY_<event-id>` in private Script Properties to five verified zero-based choice indices. Never copy that value into this repository. Setup preserves existing rows and defaults new events to AUTO with blank dates (fail closed).

The existing private tracker contains **Quiz Control** (Event ID, Manual Override, numeric result-tab ID, Open At, Close At), **Quiz Sessions** (durable start requests and secret session tokens), and **Games19Sept** (the eight requested result columns, Session ID, Submitted At). Set Manual Override to AUTO/OPEN/CLOSED without deploying. AUTO uses the existing server-side Asia/Jakarta schedule resolver: Open At is inclusive; Close At is exclusive. Missing, invalid or unreadable schedules fail CLOSED. Approved schedule: 19 Sep 2026 10:00–13:00 WIB, AUTO. Public availability and every start request evaluate server time; no scheduled job or manual action is needed. Entry screens refresh once per minute and on return to the tab. Already-admitted sessions retain their existing three-minute scoring rules. Session tokens and timing are technical private data; do not share these tabs publicly. Attendance and Download Material tabs are not changed by quiz setup.

One trimmed, lowercased email has one durable session and scored result per event. Dots and plus aliases stay intact. Sessions cannot be reclaimed merely by knowing an email; another browser receives a safe already-started/completed state. The originating tab can resume with its secret token. Browser session storage contains the token, pending answers, and retry state, never email. Closing/clearing that browser storage may prevent recovery; it does not reset the server attempt. Anonymous email entry is not verified identity and cannot prevent deliberate use of multiple email addresses.

The server issues start/deadline timestamps and scores once under a script lock. A 180-second limit allows five seconds solely for delivery. Submissions received later score zero because their answering time cannot be established; clients lock and automatically send answers at zero. Exact retries retrieve the saved result. Refresh uses the original server deadline. An abandoned expired session finalizes with zero when next resumed. No per-question writes or leaderboard polling. Apps Script has platform quotas and concurrent-execution limits; failed requests preserve an idempotent retry path rather than claiming unbounded capacity.

Transport follows the proven native POST plus random correlated acknowledgement pattern. Email and answers occur only in POST bodies; JSONP URLs carry random correlation identifiers. Participant replies contain totals/timing only, never the key or full email. Public leaderboard replies contain at most five masked emails, scores and times. Quiz pages do not initialize GA4. Public Top 5 orders by score descending, time ascending, submission timestamp ascending.

Build/check: `npm run quiz:build`, `npm run quiz:check`, `npm run attendance:build`, `npm run attendance:check`, `npm run content:build`, `npm run content:check`. QR generation reuses the published pair and verifies PNG decoding to the canonical quiz URL. Backend tests use a synthetic key, not the real seminar answers. For future events extend the owner-only provisioning mapping as well as public config; never reuse another event's key or result tab.

Release QA must exercise the deployed service with unmistakable isolated QA emails, verify private rows and WIB, then remove only those test records from both quiz tabs and restore the approved AUTO schedule (or the explicitly requested owner state). Never clear attendance/download records or real players. Keep a live verification distinction from local fixture tests.
